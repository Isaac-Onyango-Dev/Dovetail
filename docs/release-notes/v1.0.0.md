**Fits your pad to the game.**

First release. Dovetail makes a generic USB gamepad work in games that only accept an Xbox
controller — it reads the pad's raw HID reports, translates them, and presents a virtual Xbox
360 controller through ViGEmBus. No wrapper, no launch options, no per-game DLL.

---

## What's in it

**Controller detection and translation.** Raw HID reports are read directly from the device and
driven onto a virtual Xbox 360 pad. Two physical pads become two independent XInput players,
and identity is by player slot rather than by USB port — the first pad to connect becomes
player 1 regardless of which socket it is in.

**Guided calibration.** `dovetail-diag calibrate` walks you through rest noise, stick range,
triggers and an L3/R3 isolation test, then writes one profile per player slot. Prompts name
controls by position where pad families disagree about lettering, so the wizard cannot tell you
to press a button your pad does not have.

A pad with no calibration gets **no virtual device**. That is deliberate: handing it another
unit's numbers produces a controller that works but feels subtly wrong, which is far harder to
diagnose mid-game than one that plainly does not appear.

**Per-game profiles.** A lens over a calibration, never an edit of it. Deadzone, saturation and
response curve can be overridden per game; the measured centre is never touched, and the
calibration file on disk is left byte-for-byte unchanged.

**Stick feel.** Standard, Precise, Responsive and Full-range presets, with anti-deadzone, curve
and saturation adjustable by hand. A running engine picks up changes within a second.

**Tray app and notifications.** Live controller status in the notification area, per-controller
naming, re-calibrate, forget, dependency repair, and settings — including auto-start, which
migrates cleanly from any earlier install.

**Automatic dependency install.** ViGEmBus and HidHide are detected, fetched, hash-verified and
installed on first run, from the vendors' own GitHub release assets, with a pinned known-good
build as the offline fallback. Dovetail runs as a normal user; only the installer elevates, and
only for its own process.

**Reversible uninstall.** `dovetail-engine uninstall` removes only what Dovetail added — its own
HidHide allow-list entries, its own registry value, and its profiles only if you say so. Devices
Dovetail hid are un-hidden; devices you hid are left alone. ViGEmBus and HidHide stay installed,
because they are yours and not Dovetail's. Every run writes a restore point that puts it all
back.

## Requirements

- Windows 10 or 11, x64
- [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0)
- **ViGEmBus** and **HidHide** — installed for you on first run

HidHide is **required, not optional**. With it inert, the physical pad stays visible on
DirectInput and a game that polls both will bind to the raw pad and ignore Dovetail entirely
while the engine is verifiably translating. That is not a theory; it is what happened on the
first real game this project tested.

## Verified

| | |
|---|---|
| Automated checks | **252 passing** — 84 decoding/axis-scaling, 168 state machine, uninstall and HidHide ownership. Both suites run on every push. |
| Input loss | **None.** 151 of 151 HID button edges reached XInput; every packet delta exactly 1, so nothing was dropped or coalesced anywhere in the path. |
| Added latency | **Below a millisecond.** Submit-to-visible median −0.028 ms, 149 of 149 pairs within ±1 ms. Effectively instantaneous. |
| Fresh-state install | **Pass.** Full dependency install, detection, repair and uninstall in a Windows Sandbox with neither driver present. |
| Uninstall round trip | **Pass**, 24 of 24 checks, machine restored to exactly the state it was found in. |
| Two-player independence | **Pass.** Two pads drive two independent XInput slots. |

Hardware: a twin-port USB receiver reporting `VID 0x0810 / PID 0x0001` (Shanwan "Twin USB
Joystick"). The translation layer is not specific to it — calibration measures whatever byte and
bit each input actually moves — but that receiver is the only one verified end to end.

## Known limitations

**Call of Duty: Black Ops III is untested.** It is recorded as *pending install*, not as a
failure: the title was not present on the test machine, and by an explicit scope decision it was
excluded from this release's sign-off rather than substituted. Its validation pass has not been
run, so nothing is claimed about it either way. Sekiro: Shadows Die Twice is the game validated
in-game for v1.

**Rumble is not driven.** The channel exists on both sides — `VirtualPad` exposes the ViGEm
feedback event, and the pad declares a 5-byte output report on vendor page `0xFF00` — but
nothing is wired between them yet. Force feedback does nothing in this release.

**The formal per-input in-game checklist is not recorded.** Every mapped input has been
confirmed working in Sekiro, including L3/R3, but the input-by-input written record has not been
walked through.

## Install

Download `Dovetail-v1.0.0-win-x64.zip`, unzip it anywhere, and run `Dovetail.exe`. First run
offers to install anything missing, then calibrates your pad.

Keep all three executables side by side — `Dovetail.exe` launches `dovetail-diag.exe` for
calibration and `dovetail-engine.exe` for dependency work, and looks for them next to itself.

Calibration is written to `%LOCALAPPDATA%\Dovetail\profiles`, not to the install folder, so an
upgrade cannot take your measurements with it.
